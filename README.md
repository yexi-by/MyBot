# QQ Agent Harness

运行在 QQ 环境中的自主对话智能体。NapCat 提供 QQ 数据和动作；Harness 管理模型上下文、按需工具披露、群权限及隔离代码执行。默认人格为「耄耋」。

群消息是对话输入，Agent 自己判断是否回应或使用工具。只有显式发送工具会向 QQ 发言，普通模型正文不会自动发送。

## 边界

- 权限只按群配置；私聊使用统一策略。没有个人白名单、群成员角色授权或主人账号。
- 不使用业务数据库，不存聊天档案、事件账本或可恢复任务队列。会话上下文只存在有界内存中，重启清空；不会重放发送。
- 历史和媒体由 NapCat 按需提供，不能保证完整或永久可读。
- 获准使用沙箱的会话共享一个持久工作区。默认总限额 50 GB，文件、依赖和产物保留；执行进程不恢复。
- 系统安全规则独立于人格；外部消息、网页、MCP 和文件不能修改群权限。程序强制执行网络、路径和资源边界，不能仅凭提示词保证安全。

## 本地开发

需要 Python 3.14、uv、Node.js 24 和 npm。真实运行配置自行建立，不从任何示例覆盖已有配置。

```powershell
uv sync --locked
# 仅首次创建新的本地配置目录时：
Copy-Item -Recurse config.example config
uv run --locked python -m qq_agent_harness --config config/harness.toml
```

控制台默认端口 6055；开发时前端执行 `npm --prefix webui ci`、`npm --prefix webui run dev`，API 代理到 6056。后端可加 `--port 6056`。测试使用临时配置副本，不能使用真实配置。

配置 provider 的模型、协议、base_url、密钥及实际输入模态；模型必须支持工具调用，只支持 Chat Completions 和 Responses 两种协议。默认不设置采样或输出长度参数。官方协议未支持的音视频输入会明确返回能力错误，不自动转写或抽帧。

每个模型连接通过 `max_context_tokens` 声明模型的实际上下文窗口，默认 128000 token；这只是 Harness 的上下文预算，不会作为回复长度参数发送。`reasoning_effort` 可省略，省略时保留接口默认行为；明确选择后分别使用 Chat Completions 的 `reasoning_effort` 或 Responses 的 `reasoning.effort`。可选值是否可用取决于模型和接口，不会静默降级。[OpenAI 思考参数](https://developers.openai.com/api/docs/guides/reasoning)

自动压缩是固定运行行为，没有关闭开关。每次模型请求前统计系统规则、人格、当前消息、历史与知识资料、工具定义、调用结果和媒体的完整预算；达到窗口约 80% 时，先压缩旧资料，以约 50% 为目标继续本轮。保留当前输入、最近完整工具调用组及由运行器确认的动作回执；摘要仍是低权限参考资料，不能改变权限或把群友发言变成必须执行的任务。

上下文用量先按本地保守估算，再用接口返回的实际 usage 校准后续增量；缓存命中仍占上下文，媒体与不同模型的分词差异意味着这个数字不是精确 tokenizer 计数。WebUI 概览页的“正在运行”显示预算、计量来源与压缩次数，“已保留会话”显示跨唤醒累计轮次；最近活动显示压缩前后变化，不展示摘要正文或思维链。摘要随会话留在内存中，供后续唤醒继续使用，不新增聊天存储。

压缩请求和明确上下文超限后的有限恢复也计入 `runtime.max_model_rounds`。只有摘要完整、有效且实际缩小上下文后才替换原文；失败、取消或固定输入本身过大时明确结束本轮，不继续发送超预算请求，也不重放已经完成或结果未知的工具动作。

NapCat 使用反向 WebSocket 连接 `ws://<harness-host>:6055/napcat/ws`，消息格式选择数组，配置匹配的 token 和机器人账号。空 token 不开放接入。接口清单锁定 NapCat v4.18.41；见 [动作覆盖清单](docs/napcat-actions.md)。

## 群配置和工具

在 WebUI 的“会话”页添加需要启用的群（NapCat 已连接时可直接从机器人所在的群中选择），在“能力权限”中设置能力分类、具体工具覆盖和参数限制。普通成员与群主触发同一群时权限相同。默认作用于当前会话；跨群目标和跨私聊必须由来源群策略明确开放。

常用分类包括消息读取、消息发送、群管理、文件和沙箱。MCP 按服务产生独立分类。新能力不会因为模型知道名称就开放；工具必须先发现并加载，每次执行重新检查配置。工具说明和参数 schema 来自同一目录。

群内艾特、引用机器人消息或关键词唤醒，私聊启用后逐条唤醒。以“机器人账号 + 群/私聊 + 群号/私聊对象”为会话标识；同一群的所有发言者共享会话，不同群、私聊对象和机器人彼此隔离。每次唤醒在同一模型会话内开始新一轮，保留此前输入、模型可见输出、工具结果、已披露工具和压缩摘要，只补入未读过的近期 QQ 历史。轮次结束或停止不销毁会话，新的请求/发送额度按轮次重置，工具执行仍重新检查当前权限。

空闲会话不按等待时间过期。最多保留 100 个会话，序列化上下文、知识资料和未知动作参数合计预算为 256 MiB；达到任一容量上限后回收最久未使用的空闲会话，并记录回收事件。正在执行的会话不被回收，结束后重新检查容量。进程重启清空全部会话。切换模型或协议时，将已有可见历史转换为背景资料继续使用，不把旧协议或隐藏推理对象发送给新模型。

可在 WebUI 概览页停止当前轮次；停止保留已获得的上下文。中断时闭合未完成工具调用，未执行的调用标为取消，已经发起但未得到回执的调用标为结果未知。结果未知的副作用操作在后续唤醒中仍禁止直接重试。

发送超时可能已经产生副作用，返回 `unknown`，不自动重发。模型普通正文也不会作为异常兜底发送。

## 共享沙箱与部署

应用和沙箱工具链使用不同镜像；应用镜像包含后端与 WebUI。可信 runner 与代码容器分离。仅 runner 接触 Docker socket，代码容器没有服务密钥或宿主配置。

```powershell
docker build -t qq-agent-harness:1.0.0 .
docker build -f Dockerfile.sandbox -t qq-agent-harness-sandbox:1.0.0 .
```

完整部署要求、Btrfs 专用子卷、网络初始化和验收见 [沙箱说明](docs/sandbox.md)。Compose 要求明确镜像标签；首次启用沙箱前完成配额与出口初始化。未满足条件会拒绝执行，不会退化为宿主命令执行。

WebUI 的“沙箱”页支持查看用量与共享文件、清理依赖缓存、删除所选文件和清空工作区。清理前停止执行并确认范围。工作区全部共享，不能视为群间文件隔离。

生产配置、密钥及业务取值独立维护。新配置格式不读取旧 MyBot 配置，不做自动迁移。上线前逐项确认字段映射；应用只通过完整镜像部署。封存旧数据不会被任何启动或清理流程删除。

## 配置保存与运行记录

TOML 是唯一配置来源。WebUI 修改后自动保存（Ctrl+S 立即保存），保留注释和格式，并使用文件内容校验值进行乐观锁检查。文件被外部修改时可选择用本地修改覆盖、放弃本地修改或继续编辑；语法损坏时转到“设置 → 配置文件”修复原文。人格文件不得为空，引用文件只能位于配置目录。

群权限立即用于后续工具调用；人格和知识库下一轮生效。NapCat 接入、控制台服务、MCP、沙箱参数、并发会话数和活动记录条数变更需重启，WebUI 顶部会列出待重启的项并提供重启入口。普通模型输出和 reasoning 不写入日志；概览页只展示有界内存中的运行摘要。


Docker 集成测试使用专用工作区，启用方式见测试文件与沙箱说明。真实模型行为仍应使用你选择的模型和独立测试会话评估；确定性测试验证协议、权限和外部副作用，不声称能证明所有提示注入都被识别。
