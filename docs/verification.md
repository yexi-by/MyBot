## 服务商与会话模型拆分、闲时压缩（2026-10-27）

“模型”页改为“服务商”，只管连接；每个群和私聊各自选择会话模型与压缩模型，并设置上下文预算、压缩目标和输入类型。新增闲时压缩：会话闲置够久且上下文达到阈值时，用压缩模型把人格和最新知识库以外的内容压成一份摘要，不保留原文。走查使用从 `config.example` 复制到仓库外临时目录的配置，两个 fake 模型服务路径（会话模型走 Responses，压缩模型走 Chat Completions，摘要延迟 8 秒），以及 fake NapCat 反向 WS 客户端；后端 `--port 6056` 直接提供生产构建的 WebUI，由内置浏览器操作。

| 验证 | 结果与范围 |
|---|---|
| 静态检查与测试 | Ruff、格式检查、compileall 通过；basedpyright 零错误、零警告；Windows 默认测试 167 通过、6 项平台或集成测试跳过；前端生产构建通过 |
| 模型路由 | 各会话按自己的服务商和模型请求；未选模型的会话不启动推理；未设压缩模型时用会话模型且不带思考等级；引用不存在的服务商时保存被拒并给出字段路径；示例配置按新结构加载 |
| 轮内压缩目标 | 目标 50% 保留最近调用组，15% 时并入摘要；超出 10–70% 时就地报错，页头提示待修正，不写盘 |
| 校准口径判定 | 模拟接口计量为本地估算一半时，按估算超出尾部保留预算、按接口口径仍在预算内的最近调用组保留原文；计量为两倍时，按估算已达目标的摘要会再压一次，压缩后实际计量不超过目标；接口报告超窗后的强制压缩不沿用偏低的校准，压缩后的请求能放进窗口 |

| 快捷方式 | 从其他会话复制（六类设置可选）、一次应用到多个会话（只写勾选的部分和会话）、添加群时选择复制来源；被会话引用的服务商不能删除并说明数量，未使用的服务商删除前确认，默认聚焦“取消”，Esc 关闭 |
