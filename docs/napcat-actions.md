# NapCat 动作覆盖清单

锁定官方 **v4.18.41**，commit 859eb530c5801577633c2c3ae871d23586edf281。清单来自锁定版本的 router.ts 与 index.ts，不在运行时自动信任远端 schema。

当前公开 **106 个类型化工具**，逐项记录 **182 个上游动作名称**。implemented 是直接实现；adapted 归并到受控入口；internal 只供内部资源读取；excluded 有明确未暴露原因。**完整清单不表示每个原始动作都开放**。

上游为注册动作自动生成 _async 和 _rate_limited 别名；Harness 不调用这些异步/限流别名，只使用可等待最终回执的基础动作。

## 连接及多媒体

NapCat 配置反向 WebSocket，地址为 ws://Harness主机:6055/napcat/ws，消息格式使用 array，Authorization 使用配置的 Bearer token。事件和 API 回执分开处理，收到机器人自身消息不再次唤醒。

媒体优先读取明确授权的本地根路径，再由 Harness HTTP 客户端读取 URL；失败后调用 get_image/get_record/get_file 刷新。get_record(out_format=mp3) 在锁定版本返回转换后的 base64；视频/文件没有可用 URL/base64 时使用 download_file_stream。流只接受已验证消息的原生文件标识，校验分块顺序、总长度和大小上限；不把远端路径当本地路径，不要求打开 NapCat 的全局本地文件转URL开关。

工具参数中的消息 ID、群文件等资源必须属于当前获准作用范围。读取超时属于错误；有副作用的动作在提交后超时或断线属于结果未知，不自动重试。

`qq__read_media` 与 `qq__save_media_to_workspace` 共用四选一来源：`message_id` 读取已验证会话消息及转发媒体，`user_id` 读取 QQ 用户头像，`group_avatar=true` 读取当前目标群头像，`media_url` 读取 QQ 官方图床图片。URL 的初始地址和每次重定向都检查域名白名单、公网 DNS 地址、大小和图片格式。合并转发的内联副本与原生 ID 展开只选一条路径，保留消息中原本重复发送的媒体。

## 群和成员查询

- `qq__get_group_member_list` 在返回模型前按 `role` 和 `query` 筛选，再以 `offset`、`limit` 分页；默认 50 条、最多 100 条。返回 `total`、`matched`、`items`、`next_offset`，仅保留 QQ 号、昵称、名片、身份、头衔等成员资料字段。
- `qq__get_group_info` 返回规范化的基本资料，`qq__get_group_detail_info` 补充群介绍和加群问题；群主缺失或为 0 时，仅在成员列表工具及其参数获准后回填，否则返回 `owner_id=null` 和 `owner_lookup` 原因。`qq__get_group_info_ex` 保留为扩展协议标识查询，不用于替代前两项。
- `qq__get_group_member_info` 默认附带 `include_profile=true`，可选 `include_status=true`。每个附加查询单独检查对应工具、参数和目标授权，并在请求前检查取消及父工具权限；未授权或查询失败以 `profile_error`、`status_error` 返回，已获得的群成员资料仍可用。头像提示给出可直接传给 `qq__read_media` 的参数。
- 群资料、表情回应和通知查询保留有区别的底层能力及各自权限名；表情回应查询要求已知表情 ID，`fetch_emoji_like` 另支持私聊和 cookie 分页。成对状态操作的说明直接指向反向工具，消息表情回应由 `set_msg_emoji_like.set` 选择添加或取消。
